# Spec contradictions and resolutions

Rule: when specs disagree, the Dart code in `../lib` wins (ARCHITECTURE.md); for native-only design choices, the already implemented `:core:*` code and spec 14 win.

## Batch: storage, kinds, formatting, module names (2026-10-20)

1. **Non-secret pref store.** Truth: one shared `KeyValueStore` (DataStore `app_prefs`) and one `SecureStore` (DataStore `secure_prefs`, Keystore alias `einundzwanzig_secure_store_v1`), both in `:core:data` (implemented: `core/data/.../PreferencesDataStores.kt`, `AndroidKeystoreKeyProvider.kt`). Domain repositories are typed views on these stores and open no DataStore file of their own. Fixed: 01 §4.3 (`identity_prefs` and `SecretStore` removed, module listing), 06 (§4 storage note, §12 storage, §13 `PlatformProofRepository`), 12 §4/§11/§13 (`settings.preferences_pb` removed; `SettingsRepository(store: KeyValueStore)` in `:data:settings`).
2. **Flutter prefs migration.** Truth: spec 14 §4.6–§4.8. The central `:data:migration` makes one generic copy into `app_prefs`, keeps its state in `noBackupFilesDir/flutter_migration/state.json`, and deletes the Flutter files only at cleanup or app reset (F6). No `SharedPreferencesMigration` per domain, no `LegacyFlutterPrefs` importer per domain, and no domain keeps reading `FlutterSharedPreferences.xml`. Fixed: 13 §4.2 and the §11 persistence row, 12 §4/§11/§13/§10 test 12/§14 risk 1, 01 §4.4 steps 1–3 (no `native_migration_done` pref, no immediate deletion; now defers to 14 §4.7).
3. **`diagnostic_log` storage.** Truth: the implemented `FileLogStore` in `:core:common` (`core/common/.../log/LogStore.kt`) writes `filesDir/diagnostic_log.jsonl` (JSON lines, atomic rename) and `filesDir/diagnostic_verbose`. The migration passes the Flutter `diagnostic_log`/`diagnostic_verbose` values to `AppLogger.importLegacy(raw, verbose)`, which redacts them, merges them in front of the native entries and adds one INFO count entry (a corrupt buffer gives a WARN entry and is not imported). Neither key goes into `KeyValueStore`. Fixed: 14 rows 98/99, §4.3.4 (new routing row), §4.10; 12 §4 and §11 (`diagnostic_log.json` → `.jsonl`).
4. **Kind 21001.** Truth (badge_security.dart:520–556): the reputation-QR (21v3) signature envelope, with tags `[]`, content = QR JSON, never published. There is no revocation event; the comment `21001 Badge-Widerruf` at nip46_client.dart:102 is stale. Fixed: 01 §6.2 kind legend.
5. **Kind 30079 d-tag.** Truth (coattendance_service.dart:184–195, 265–279): `d = attendanceKey(meetupEventId, signerNpub, isEvent)` = `<meetupEventId>@<last 12 chars of signer npub>`, `ev|<meetupEventId>` for event badges, plain `meetupEventId` only when the signer is empty (legacy). Fixed: 03 §2 cleanup rationale and §10.
6. **`favorite_meetups` / `home_meetup`.** Truth: portal meetup IDs. City names occur only as the legacy form, which the picker maps to IDs (09 §8.4, persisted when the user saves). The App Review demo still writes `'Berlin'`. The Dart comment "Stadtnamen" (models/user.dart:16) is stale. The migration copies the values verbatim. Fixed: 14 rows 27/28, 01 §4.1 table.
7. **Haptics.** Truth (Flutter engine PlatformPlugin.java:197–210): selectionClick→`CLOCK_TICK`, lightImpact→`VIRTUAL_KEY`, mediumImpact→`KEYBOARD_TAP`, heavyImpact→`CONTEXT_CLICK`, vibrate/standard→`LONG_PRESS`. Specs 12 §8.11 and 04 were correct. Fixed: 05 §11 and 07 §11, which now point to 12 §8.11.
8. **Gradle module names.** Truth: ARCHITECTURE.md plus `settings.gradle.kts` (`:core:<x>`, `:data:<x>`, `:feature:<x>`). Logging = `:core:common` (package `core.common.log`; no `:core:log`/`:core:logging`). Network = `:core:network`. Prefs/secure store = `:core:data`, settings repo = `:data:settings` (no `:core:prefs`). Signer API (`SigningService`/`NostrSigner`) = `:data:identity`; `:core:nostr` holds only the event model and id/BIP-340 primitives (no `:core:signing`). There is no `:core:security`: `ScreenSecure`/`SecretClipboard` → `:core:ui`, `DeviceAuthenticator`/`DeviceIntegrityService` → `:data:identity`. Portal/location = `:data:meetups` (no `:core:portal`/`:core:location`). Fixed: 02 §13 (hyphenated names), 07 §12, 11 §13, 12 §13, 01 §13, 09 §13.
9. **NIP-46 permissions.** Truth (nip46_client.dart:110–128): `requestedPerms` already contains `sign_event:21001`, `sign_event:21002` and `sign_event:30078`, so nothing is missing. Fixed: 04 §3 signing note and R-19, which now say "already included, keep".
10. **Sort stability threshold.** Truth (dart-sdk `lib/internal/sort.dart`: `_INSERTION_SORT_THRESHOLD = 32` on `right - left` with an inclusive `right`): stable for ≤ 33 elements. Spec 03 §7.2 already says "33 or fewer / 34 or more". No change needed.
11. **UserProfile npub precedence.** Truth (models/user.dart:104–118): an external signer npub overrides the SecureKeyStore npub, which overrides prefs `nostr`. Spec 03 §2.1.2 step 2 already lists the order highest first and matches. No change needed.
12. **Case mapping.** Truth (verified with Dart VM and JDK 17): Dart `toLowerCase` uses no final-sigma rule (`ΟΔΟΣ`→`οδοσ`, Java `οδος`), maps `İ` (U+0130) to `i` (Java `i̇`, U+0069 U+0307), and Dart `toUpperCase` keeps `ß` (Java `SS`). `Locale.ROOT` does not fix these differences. Spec 02 §8.14 `DartString.lower/upper/trim` is canonical. Fixed: 03 §3 `nd:` identity key, 03 §8.1 filter (comment "≈ Kotlin lowercase(Locale.ROOT)" removed), 03 §14 case-mapping note, 04 §7.9 (Locale.ROOT applies to number formatting only; case mapping goes through DartString, including npub input normalisation).
13. **`toStringAsFixed` porting rule.** Truth: one shared helper, the implemented `Double.toStringAsFixed(fractionDigits)` (plus Int/Long overloads) in `:core:common` `core.common.dart.DartCompat`. It rounds the exact binary value HALF_UP, always uses `.`, and falls back to Dart `toString` for ≥ 1e21/NaN/∞. `String.format` and local copies are never allowed. Fixed: 12 §7 and §14 risk 14 (code block replaced), 14 §3.1.4, F11 and R15, 13 §7.3 and §13 (`DartNum.kt`), 10 §7 (`dartFixed6` kept only as a reference equal to `v.toStringAsFixed(6)`), 04 §7.9, R-13 and §13 util, 09 §2/§8 (`nbKmAway`).
14. **Negative zero.** Truth: Dart `(-0.0).toStringAsFixed(1) == "-0.0"`, so the sign check must also catch `-0.0` (the shared helper uses `x < 0 || (x == 0.0 && 1/x < 0)`). The snippet in 14 §3.1.4 (`if (x < 0)`) printed `"0.0"`; it was removed together with the identical snippet in 12 §7, and both now reference the shared helper (item 13).
15. **Widget refresh at app start.** Truth (lib/main.dart:100–105): `refreshBitcoin` + `refreshNews` run only in `widgetBackgroundCallback` (refresh button). Separately, Home `initState` calls `refreshNews()` (home_screen.dart:203). Spec 10 §2.10 already states this and tells the port not to refresh on app start; 12 §2.1 step 5 and 14 §3.1.4/§3.1.6 match. No change needed.
16. **Portal login protocol.** Truth (portal_api_service.dart:11–19, 163–185): stateless NIP-42-style kind-22242 event with `["challenge", k1]`, where the app generates k1 itself, posted to `/api/mobile/token`. Not NIP-98. Spec 12 §5 already says this explicitly ("Not NIP-98"). No change needed.
17. **OSM tile user agent.** Specs 09 §5.5 and 14 §2 say `userAgentValue = BuildConfig.APPLICATION_ID` (`space.einundzwanzig.meetup`); spec 03 §5 suggests `space.einundzwanzig.meetup/<version> (Android)`. Truth: the implemented `OsmConfiguration` in `:core:map` sends `<applicationId>/<versionName> (Android)` (bare package if the version is unreadable). Both satisfy the OSM tile policy (identifying, not a library default); the version lets OSM ops tell app releases apart. Flutter sent `flutter_map (space.einundzwanzig.meetup)`, so neither form is byte parity.
